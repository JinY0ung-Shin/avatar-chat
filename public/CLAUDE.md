# public — Claude notes

Frontend cautions. Vanilla JS, **no framework, no build step, no bundler**. Read with the root `CLAUDE.md` Frontend + CSP sections.

**Design language → [`docs/DESIGN.md`](../docs/DESIGN.md).** Calm productivity tool (neutral base, teal as accent only); 4px-base spacing scale; per-screen density (chat compact / settings comfortable / admin compact). All color/spacing/radius/type goes through `:root` tokens — no hardcoded hex/px. When adding or fixing UI, follow that doc and converge drift toward it (don't introduce ad-hoc values).

## Verification is weak here — be conservative
- **`node --check` (syntax only) is the ONLY automated check** for the frontend JS (the `pretest` hook now runs it over `public/app.js` AND every `public/js/*.js` module; `tsc` is server-only). It validates **syntax, not behavior** and does NOT catch a missing/wrong import — there are NO frontend tests, and the app **cannot be runtime-verified in this environment** (corporate `HTTP_PROXY` intercepts `localhost`, no browser engine installed). So any JS change rides on careful reading + `node --check` + a **static import-graph check** (every `import {X} from './y.js'` resolves to a real `export` — `node --check` won't catch a missing import, even inside a `${...}` template literal) + a human browser smoke-test. Treat frontend edits as higher-risk than server edits and keep them mechanical/behavior-preserving unless you can have someone load it in a browser.
- **CSS has NO automated check** — sanity-check edits with two static scans: (1) brace/paren balance, and (2) an **undefined-token scan** (collect every `--x:` definition, then assert every `var(--x)` reference sans fallback resolves to one — catches the silent-invalid-prop class in CSS gotchas below). Then a human light+dark smoke test.

## Structure
- **The frontend was split into ES modules (2026-06)** — no bundler (CSP `script-src 'self'` + same-origin `/vendor` ESM imports allow it). `public/app.js` is now a thin ~12-line entry that imports `boot` and runs it; all feature code lives in **`public/js/*.js`** (`core`, `chat`, `settings`, `admin`, `explore`, `routines`, `inbox`, `auth`, `nav`, `loaders`, `lifecycle`, `shell`, `avatar-image`). `chat.js` is itself a thin barrel re-exporting its 19 public symbols from **`public/js/chat/*.js`** (`panes`, `view`, `slash`, `capabilities`, `composer`, `assistant`, `stream`, `conversations`); external code keeps importing from `./chat.js`. Likewise the stylesheet is split into **`public/styles/*.css`** (`00-tokens` → `70-modals-groups`, loaded via ordered `<link>` tags in `index.html`; cascade order = filename order). The old single `styles.css` is gone.
- **`public/js/core.js` is the LEAF primitives module** — ALL shared mutable state + core primitives (`state`, `dom`, `abortController`, `sessionExpired`, the `el()` helper, `notify`, the `api`/fetch wrappers, `newId`, `timeLabel`, `renderMarkdown`) live here and everything else imports them; forking them across modules silently forks state. **core must NOT import feature modules** (auth/chat/loaders/shell) or it forms an import cycle — orchestration that needs feature teardown is registered INTO core via a hook instead: session-expiry teardown lives in `lifecycle.js` and registers via `setSessionExpiredHandler`; the 401 paths call `core.triggerSessionExpired()`. Follow that pattern (register a handler, don't import upward) for any new core→feature need.

## Behavior gotchas (don't "fix" these)
- **No reactivity.** After mutating `state` you MUST explicitly call `renderView()` / the relevant render. But some cards (settings profile/visibility/secrets) update **in place** on purpose, to avoid wiping unsaved form text on a re-render — preserve that; don't replace them with a full re-render.
- **`renderExploreGrid` / `renderExploreGridImpl` late-bound indirection is deliberate** (the search box calls the grid before the impl is assigned) — not dead code.
- **`RUNTIME_BADGE_LABELS.claude === null` → no badge.** `.runtime-claude` CSS is unreachable, but `.runtime-blocked`/`.runtime-local` are built dynamically via `runtime-${raw}` (a class-name grep misses them) — keep those CSS rules.
- Dynamically-created elements share the global stylesheet — avoid bare generic class names (e.g. `main`) that collide with layout rules (root CLAUDE.md has the `.agent-node main` cautionary tale).
- **Group-knowledge toggle saves a per-USER default, and the save is intentionally fire-and-forget with NO readback.** A new chat pane seeds `groupKnowledgeOff` from `defaultGroupKnowledgeOff(avatar)` (own avatar only — colleague chats and existing conversations pass their persisted per-conversation value explicitly). This is what lets the toggle reach the **auto-greeting**, which fires before the user can touch the composer (the value rides the greeting's chat POST, which the server already applies). `setGroup` → `saveGroupKnowledgeDefault` updates `state.user.groupKnowledgeOffDefault` optimistically and PUTs `/api/me/group-knowledge-default` in the background — it deliberately does NOT overwrite `state.user` from the response (rapid toggles can resolve out of order; the optimistic value is always the latest pick) and only toasts on failure (the current conversation still got the selection via its own chat POST). Don't "fix" this into an await-and-sync.

## CSS gotchas (styles.css)
- **Input chrome comes ONLY from `.field input`, not a global rule.** The global `button,input,select,textarea` rule (~L221) sets just `font`/`color: inherit` — there is NO global border/padding/radius/focus-ring. All input styling is the canonical `.field input, .field select, …` rule (~L453) and applies ONLY when the control sits inside a `.field` ancestor. A bare `<input>` dropped into a custom row renders unthemed — exactly how the 권한·연결 tab drifted (its `.secret-preset-row` inputs got only bg+border-color, no border-width/radius/padding/focus-ring). New form controls MUST sit inside `.field` OR be folded into that canonical selector — never restyle inputs ad hoc per row.
- **Code-block colors are deliberately FIXED across light AND dark** (source comment ~L124) via `--code-bg/-fg/-fg-muted/-overlay/-overlay-strong/-ok/-danger`. Do NOT remap them to semantic `--ok`/`--danger` — those invert in dark mode and are unreadable on the always-dark code surface. Code-surface state colors get their own `--code-*` tokens.
- **Undefined CSS custom props fail silently.** `var(--undefined)` with no fallback renders invalid with no console error (`color: var(--text-muted)` silently inherits; `outline: … var(--focus)` just breaks). Both were latent bugs (→`--muted`/`--accent`). Scan after CSS edits (see Verification above).

## Client ↔ server contracts mirrored by hand
There is no shared module across the TS/JS boundary, so the client re-implements several server validators. Update these in lockstep:
- `normalizeTagList` ↔ server `normalizeHashtags`
- repo-href building ↔ server `githubHost` resolution
- the schedule form (`buildScheduleForm` / routine modal) ↔ server `routineSchedule.ts` (daily/weekly/interval semantics)

## CSP
`app.ts` serves a strict same-origin CSP (`script-src`/`connect-src` `'self'`, `img-src 'self' data:`). Remote `<img>` in rendered markdown is BLOCKED and cross-origin fetch is impossible — widen the directive in `app.ts` if a feature needs it. There is no inline `<script>`, so `script-src 'self'` is safe.
